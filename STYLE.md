# Стандарт оформления базы знаний Slon Privacy

## Главный принцип

Все новые статьи базы знаний Slon Privacy должны оформляться по существующим эталонным статьям.

Не нужно придумывать новый дизайн, новые классы или локальные стили.

---

## Эталонные статьи

### Простая статья

Использовать структуру и оформление статьи:

```text
macos.md
```

Подходит для:

- одной инструкции;
- одного приложения;
- статьи без вкладок.

### Статья с вкладками

Использовать структуру и оформление статьи:

```text
android.md
```

Подходит для:

- нескольких приложений;
- нескольких вариантов установки;
- статьи с переключаемыми вкладками.

---

## Общие стили

Каждая новая статья должна подключать общий файл стилей:

```liquid
{% include knowledge-styles.html %}
```

Не добавлять локальный блок:

```html
<style>
...
</style>
```

Если для статьи требуется новый элемент оформления, сначала нужно проверить, нельзя ли собрать его из уже существующих компонентов.

---

## Разрешённые компоненты

Использовать существующие классы из эталонных статей и `knowledge-styles.html`, в том числе:

```text
app-tabs
app-tab-buttons
app-tab-button
app-tab-panel
guide-note
guide-video-section
guide-video
guide-step
guide-step-number
guide-step-content
guide-simple-list
guide-warning
guide-success
guide-faq
guide-image
guide-image-small
guide-inline-tab-link
```

Не переименовывать классы и не создавать для каждой статьи отдельный набор классов.

---

## Правила для статей с вкладками

За основу всегда брать актуальный файл `android.md`.

Сохранять:

- `data-app-tabs`;
- `role="tablist"`;
- `role="tab"`;
- `aria-selected`;
- `aria-controls`;
- уникальные `id` панелей;
- `role="tabpanel"`;
- класс `is-active` у первой активной вкладки;
- подключение:

```liquid
{% include app-tabs-script.html %}
```

Не упрощать структуру вкладок без необходимости.

---

## Изображения

Основное изображение:

```html
<img
  class="guide-image"
  src="{{ site.baseurl }}/assets/img/..."
  alt="Описание изображения"
  loading="lazy">
```

Компактное изображение:

```html
<img
  class="guide-image guide-image-small"
  src="{{ site.baseurl }}/assets/img/..."
  alt="Описание изображения"
  loading="lazy">
```

Для каждого изображения обязательно указывать понятный `alt`.

---

## Видео

Использовать структуру из актуальной статьи `android.md`:

```html
<section class="guide-video-section" aria-labelledby="video-title">
  <h2 id="video-title">Видеоинструкция</h2>
  <p>Краткое описание видео.</p>

  <video class="guide-video" controls playsinline preload="metadata">
    <source src="{{ site.baseurl }}/assets/video/..." type="video/mp4">
    Ваш браузер не поддерживает воспроизведение видео.
  </video>
</section>
```

Если видео нет, блок полностью удалить.

---

## Тёмная тема

Все статьи должны корректно работать в светлой и тёмной теме.

Нельзя добавлять в статью жёстко заданные цвета, например:

```css
background: #fff;
color: #222;
```

Цвета и оформление должны приходить из `knowledge-styles.html`.

---

## Перед публикацией

Проверить:

- статья основана на `macos.md` или `android.md`;
- подключён `knowledge-styles.html`;
- нет локального `<style>`;
- структура вкладок сохранена;
- ссылки открываются;
- пути к изображениям и видео верны;
- у изображений есть `alt`;
- у изображений есть `loading="lazy"`;
- статья корректно выглядит на мобильном устройстве;
- статья корректно выглядит в тёмной теме;
- HTML-теги правильно открыты и закрыты.

---

## Рабочая формулировка для новых задач

При создании новой статьи использовать правило:
